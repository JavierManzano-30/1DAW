Guía SQL Minimalista & Colorida

Esta guía explica las consultas más importantes de MySQL, desde lo más básico hasta lo avanzado. Se compone de 19 secciones con ejemplos, tips y quizzes.

1. SELECT básico

Explicación: SELECT sirve para leer datos de una tabla. Por ejemplo, SELECT * obtiene todas las columnas, aunque no es lo ideal en producción por rendimiento. 

SELECT *
FROM Empleados;
Tips & Tricks 📌:
  • Mejor especificar columnas: SELECT Nombre, Apellido.
  • Sin ORDER BY, el orden de filas no está garantizado.
Quiz
  • ¿Cómo muestras sólo Nombre y Salario?
  • ¿Por qué SELECT * se desaconseja en grandes tablas?
¡Vamos bien! ✅

2. WHERE, AND, OR, NOT

Explicación: WHERE filtra filas. AND, OR y NOT permiten combinar y negar condiciones lógicas. 

SELECT *
FROM Empleados
WHERE DepartamentoID = 3
   OR (DepartamentoID = 1 AND Salario > 50000);
Tips 🧠:
  • AND evalúa ambas condiciones, OR con que una sea verdadera basta.
  • Usa paréntesis para aclarar la prioridad lógica.
Quiz
  • ¿Cuál es la diferencia entre AND y OR?
  • ¿Cómo negarías que DeptID = 2?
Si lo respondes, vas genial. 👍

3. ORDER BY

Explicación: Ordena los resultados por una o varias columnas. Usa ASC (ascendente) o DESC (descendente). 

SELECT Nombre, Salario
FROM Empleados
ORDER BY Salario DESC;
Tips 📌:
  • ASC es por defecto. DESC es para mayor a menor.
  • Puede usarse en varias columnas: ORDER BY Depto ASC, Salario DESC.
Quiz
  • ¿Qué pasa si no pones ORDER BY?
  • ¿Cómo ordenarías por Apellido ascendente?
¡Sigue así! 🚀

4. LIMIT

Explicación: LIMIT controla el número de filas devueltas, útil para top N o paginación. 

SELECT Nombre, Salario
FROM Empleados
ORDER BY Salario DESC
LIMIT 5;
Tips 🧠:
  • LIMIT offset, count sirve para paginar.
  • Sin ORDER BY no sabrás qué filas concretas salen.
Quiz
  • ¿Cómo obtendrías sólo las 3 filas con mayor salario?
  • ¿Cómo harías para mostrar de la fila 20 a la 29?
¡Perfecto! 🏆

5. DISTINCT

Explicación: Elimina duplicados en las columnas seleccionadas. 

SELECT DISTINCT DepartamentoID
FROM Empleados;
Tips 📌:
  • Combina con una o varias columnas.
  • GROUP BY también obtiene valores únicos, pero DISTINCT es más directo.
Quiz
  • ¿Qué pasa si seleccionas DISTINCT Depto, Salario?
  • ¿En qué caso preferirías GROUP BY?
¡Sigue adelante! ✔️

6. Funciones agregadas

Explicación: SUM, AVG, COUNT, MAX, MIN para cálculos sobre grupos de filas. 

SELECT 
  COUNT(*) AS Total,
  AVG(Salario) AS Promedio,
  MAX(Salario) AS SalarioMax
FROM Empleados;
Tips 🧠:
  • COUNT(col) ignora NULL, COUNT(*) no.
  • Para usarlas junto a columnas normales, necesitas GROUP BY.
Quiz
  • ¿Diferencias entre COUNT(*) y COUNT(col)?
  • ¿Cómo obtendrías la suma total de salarios?
¡Bien! 🎉

7. GROUP BY y HAVING

Explicación: GROUP BY agrupa filas para funciones agregadas. HAVING filtra grupos resultantes. 

SELECT DepartamentoID,
       COUNT(*) AS NumEmp,
       AVG(Salario) AS SalarioProm
FROM Empleados
GROUP BY DepartamentoID
HAVING AVG(Salario) > 40000;
Tips 📌:
  • WHERE filtra antes de agrupar, HAVING después.
  • Incluye en GROUP BY las columnas no agregadas en SELECT.
Quiz
  • ¿Por qué no se puede usar AVG() en WHERE?
  • ¿Qué pasa si omites una columna del GROUP BY?
¡Excelente! 😎

8. Fechas y texto

Explicación: MySQL ofrece funciones de fecha (p.ej. YEAR(), MONTH(), DATEDIFF()) y de texto (CONCAT(), UPPER(), SUBSTRING()). 

SELECT Nombre,
       YEAR(FechaContratacion) AS Anio,
       CONCAT(Nombre, ' ', Apellido) AS NombreCompleto
FROM Empleados;
Tips 🧠:
  • DATE_FORMAT(fecha,'%d-%m-%Y') para formatear.
  • LOWER, UPPER, SUBSTRING para manipular cadenas.
Quiz
  • ¿Cómo extraerías el día y el mes de una fecha?
  • ¿Para qué usarías TRIM()?
¡Súper! 🚀

9. Subconsultas

Explicación: Consultas anidadas en SELECT, WHERE o FROM para filtrar o calcular valores. 

SELECT Nombre
FROM Empleados
WHERE Salario > (
  SELECT AVG(Salario) FROM Empleados
);
Tips 📌:
  • Si la subconsulta devuelve varias filas, usa IN o EXISTS.
  • Las subconsultas correlacionadas se ejecutan por cada fila externa, ojo con rendimiento.
Quiz
  • ¿Cómo encontrarías empleados por encima del salario promedio de su departamento?
  • ¿Cuándo es mejor un JOIN que una subconsulta?
¡Adelante! 🌟

10. JOINs

Explicación: Combina filas de varias tablas según llaves foráneas. INNER JOIN solo filas coincidentes, LEFT JOIN conserva todas de la izquierda, etc. 

SELECT e.Nombre, d.NombreDepto
FROM Empleados e
INNER JOIN Departamentos d
  ON e.DepartamentoID = d.DepartamentoID;
Tips 🧠:
  • MySQL no soporta FULL JOIN nativamente (usa UNION de LEFT y RIGHT).
  • Self join: la tabla se une a sí misma.
Quiz
  • ¿En qué caso usarías LEFT JOIN?
  • ¿Cómo relacionar Empleados con sí misma para jefes-subordinados?
¡A practicar JOINS! 🏅

11. IN, BETWEEN, LIKE

IN comprueba si un valor está en una lista. BETWEEN verifica rangos inclusivos. LIKE busca patrones en texto (% y _). 

SELECT Nombre
FROM Empleados
WHERE Apellido LIKE '%ez';
Tips 📌:
  • BETWEEN x AND y incluye x e y.
  • LIKE 'A%' busca palabras que comienzan con A.
Quiz
  • ¿Cómo filtrar salarios entre 30000 y 50000?
  • ¿Qué apellidos encontraría LIKE '%ez'?
¡Muy bien! 🏆

12. CASE y IF

Explicación: CASE WHEN y IF() permiten hacer lógica condicional en las consultas. 

SELECT Nombre,
CASE 
  WHEN Salario >= 60000 THEN 'Alto'
  WHEN Salario >= 40000 THEN 'Medio'
  ELSE 'Bajo'
END AS Nivel
FROM Empleados;
Tips 🧠:
  • CASE es estándar, IF es propia de MySQL.
  • La primera condición verdadera gana.
Quiz
  • ¿Cómo crear 3 niveles de antigüedad usando CASE?
  • ¿En qué caso IF() es suficiente?
¡Condicionales listas! ✨

13. Funciones de ventana

Explicación: Desde MySQL 8.0: OVER, ROW_NUMBER, RANK, etc. Cálculos avanzados sin colapsar filas (ranking, acumulados). 

SELECT Nombre, 
       ROW_NUMBER() OVER(
         PARTITION BY DepartamentoID
         ORDER BY Salario DESC
       ) AS Rango
FROM Empleados;
Tips 🧠:
  • RANK() y DENSE_RANK() manejan empates distinto.
  • LAG(col) y LEAD(col) acceden a la fila previa o siguiente.
Quiz
  • ¿Cómo sumar de forma acumulada los salarios por dpto?
  • ¿Qué diferencia hay entre ROW_NUMBER y RANK?
¡Poder analítico! 🔮

14. Vistas

Explicación: CREATE VIEW define una “tabla virtual” basada en una consulta. Útil para simplificar el acceso o proteger datos. 

CREATE VIEW EmpleadosConDepto AS
SELECT e.ID, e.Nombre, d.NombreDepto
FROM Empleados e
JOIN Departamentos d
  ON e.DepartamentoID = d.DepartamentoID;
Tips 📌:
  • Las vistas no almacenan datos (no son tablas físicas), sino consultas definidas.
  • Algunas vistas complejas no pueden actualizarse directamente.
Quiz
  • ¿Por qué crearías una vista en vez de consultar la tabla directamente?
  • ¿Cómo verías a los empleados con Salario > 50000 usando una vista?
¡Perfecto! 🚀

15. Procedimientos

Explicación: Stored Procedures guardan lógica SQL (condiciones, bucles). Se llaman con CALL. 

CREATE PROCEDURE EmpleadosPorDepto(IN p_dept INT)
BEGIN
  SELECT Nombre, Apellido
  FROM Empleados
  WHERE DepartamentoID = p_dept;
END;
Tips 🧠:
  • Usa DELIMITER distinto en consola al crearlos.
  • Parámetros IN, OUT o INOUT para flexibilidad.
Quiz
  • ¿Cómo crearías un procedimiento que actualice el salario un 10%?
  • ¿Qué es INOUT?
¡Listo para rutinas avanzadas! 🔧

16. Triggers

Explicación: Se activan automáticamente al hacer INSERT, UPDATE o DELETE. Usados para auditoría, integridad, etc. 

CREATE TRIGGER trg_incrementar
AFTER INSERT ON Empleados
FOR EACH ROW
BEGIN
  UPDATE Departamentos
  SET NumeroEmpleados = NumeroEmpleados + 1
  WHERE DepartamentoID = NEW.DepartamentoID;
END;
Tips 📌:
  • NEW hace referencia a la nueva fila, OLD a la anterior en update/delete.
  • Evita lógica muy pesada para no afectar el rendimiento global.
Quiz
  • ¿Para qué sirve un trigger BEFORE INSERT?
  • ¿Qué sucede si un trigger produce cambios que vuelven a disparar el mismo trigger?
¡Cuídalo! ⚠️

17. Índices

Explicación: Estructuras para agilizar búsquedas por columnas. A cambio, INSERT/UPDATE/DELETE son más lentos. 

CREATE INDEX idx_apellido
ON Empleados(Apellido);
Tips 🧠:
  • SHOW INDEX FROM tabla para verlos.
  • En columnas con poca variedad (booleana) no ayudan mucho.
Quiz
  • ¿Por qué ralentiza las inserciones masivas?
  • ¿Diferencia entre PRIMARY KEY y UNIQUE INDEX?
¡Optimización! 🌟

18. Transacciones

Explicación: START TRANSACTION, COMMIT, ROLLBACK para agrupar operaciones en bloque atómico (todas o ninguna). 

START TRANSACTION;
UPDATE Empleados
  SET DepartamentoID = 2
  WHERE ID = 1;

UPDATE Departamentos
  SET NumeroEmpleados = NumeroEmpleados + 1
  WHERE DepartamentoID = 2;

COMMIT;
Tips 📌:
  • Si algo falla, ROLLBACK revierte todo.
  • Muchas sentencias DDL hacen COMMIT implícito en MySQL.
Quiz
  • ¿Qué pasa si no confirmas con COMMIT?
  • ¿Para qué sirve SAVEPOINT?
¡Crucial para integridad! ✅

19. Seguridad

Explicación: GRANT otorga privilegios a un usuario, REVOKE los quita. Ideal para controlar quién puede hacer qué. 

CREATE USER 'analista'@'localhost' IDENTIFIED BY 'abc123';
GRANT SELECT, INSERT ON Empresa.* TO 'analista'@'localhost';
REVOKE INSERT ON Empresa.* FROM 'analista'@'localhost';
Tips 🧠:
  • Evita GRANT ALL en producción, da solo permisos mínimos necesarios.
  • SHOW GRANTS FOR 'usuario'@'host' para ver permisos actuales.
Quiz
  • ¿Cómo darías SELECT sólo en 1 tabla?
  • ¿Para qué sirve GRANT OPTION?
¡Protege tu BD! 🔒
